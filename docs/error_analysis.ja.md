行の抽出は `uv run scripts/sample_lines.py`（seed 0）で、結果は `out/mt/sample.jsonl` に出ます。

各行は `out/mt/viewer.html` で、ページの画像と並べて確認できます。

判定は Claude が下書きし、人が確認する前提のものです。1 行ずつの判定は主観を含みます。

## 判定の基準

- **正しい**: 意味が合っていて、口調も自然。正解訳と言い回しが違ってもかまいません。
- **軽微**: 意味は通るが、ニュアンス、口調、言葉の一部が落ちている。
- **誤り**: 意味が違う、主語を取り違えている、大事な部分が抜けている。

## 分かったこと

- **Qwen の大きな弱点は、主語の補い方です。** 日本語で省かれた主語や相手を取り違える誤りが、
  Qwen3-4B-lora で 3 行（#10、#11、#27）、Qwen3-1.7B-lora で 3 行（#10、#11、#20）ありました。
  多くは "I" で埋めてしまうものです。Kimi-K3 は前後の文脈から正しく補えています。前のページのコンテキストが効かなかった（README の Ablations）ことと
  合わせると、Qwen は与えられた文脈をうまく使えていない可能性があります。
- **一番多いのは意味の取り違えです。** 多義語や慣用句で起こりやすく、「似合う」（#22）、
  「食あたり」（#19）、「決まってる」（#26）、「単独でも…」（#18）などです。Qwen3-4B-lora で 7 行、
  Qwen3-1.7B-lora で 9 行と、モデルが小さいほど増えます。
- **口調は Kimi-K3 のほうが残ります。** どもり（#28）、確認の「だろ?」（#21）、無線の硬い調子（#14）
  を Qwen は落としがちです。
- **途切れた言葉は、3 つとも苦手です。** 「お...に...」（鬼、#17）は Kimi-K3 もローマ字のまま
  にしました。「さま...」（#13）も 3 つとも "sama" のままです。
- **正解訳そのものが意訳寄りで、ずれている行があります。** #7（正解訳 "after seeing her face."）、
  #10、#14、#18 などは、正解訳が別の行の内容を含んでいるか、大きく意訳されています。chrF++ の
  ばらつきの一因です。

## 大文字・小文字の癖

LoRA の後の Qwen は、行の 90% 以上が小文字で始まるようになりました（例: "i'm alive..."）。
OpenMantra の正解訳は 85% の行が小文字で始まり、LoRA がこの書き方を覚えたためです。ベースの
Qwen と Kimi-K3 は 2〜8% です。chrF++ は大文字と小文字を区別するので、LoRA の向上の一部は訳の
質ではなく、この癖を真似たことによるものです。大文字・小文字をそろえて測り直した結果は
[README](../README.md#results) にあります。

## 改善案

上の観察（30 行）からの案で、どれもまだ試していません。効果は実験で確かめる必要があります。

| 問題 | 見立て | 案 |
|---|---|---|
| 主語・代名詞の取り違え | 誰が誰に話しているかを、テキストだけでは判断しにくい | 前のページの英訳も渡す。プロンプトに「省略された主語は文脈から補い、"I" と決めつけない」と書く。根本的には画像を見せる（Qwen3-VL などの視覚言語モデル） |
| 意味の取り違え | モデルが小さいほど多い | モデルを大きくする。Qwen3 の思考モードを試す（速度と費用は悪くなる）。学習データを増やす |
| 口調が落ちる | 正解訳自体がどもりなどを落としていて、LoRA がその書き方を覚えた | Kimi-K3 の訳で学習する蒸留 |
| 途切れた言葉・敬称 | 途切れた語を元の語として読めていない | プロンプトに規則を足す（例: o...ni... → de...mon...、敬称は英語の呼び方にする）。本ごとの用語集を入れる |
| 評価のずれ | 正解訳が意訳寄りで、小文字が多い | 大文字・小文字を区別しない chrF++ を主な指標にする。COMET を入れる。LLM や人による判定を少し加える。学習前に正解訳の書き出しを大文字にそろえる |

蒸留について:

- Kimi-K3 の訳は 209 ページ分がすでにあります。fold ごとに、学習に使う 4 冊の正解訳を Kimi-K3 の訳に
  置き換えれば、追加の API 料金なしで学習できます。
- Kimi-K3 の出力を学習に使ってよいかは、Moonshot と Nebius の利用規約で確認が必要です。
- 評価が正解訳との chrF++ のままだと、蒸留で訳が良くなっても点数に出にくい可能性があります。
  評価の改善とセットで試します。

進める順番:

1. 評価の改善（大文字・小文字をそろえた chrF++、COMET）。これがないと、他の改善の効果を正しく
   測れません。COMET は Week 3 で EC2 を使うときに一緒に計算します。
2. プロンプトの改善（主語の規則、途切れた語の規則、用語集）。安く試せます。Kimi-K3 にも同じ

3. 蒸留。規約を確認してから試します。
4. 画像を使う。Fukidashi の改造と一緒に考えます。
